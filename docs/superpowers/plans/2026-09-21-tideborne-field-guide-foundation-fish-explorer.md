# Tideborne Field Guide Foundation + Fish Explorer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Tideborne's current hand-built static wiki shell with a production Astro/Starlight site that consumes `docs/wiki/`, preserves the official GitHub Pages surface, and ships a working data-backed Fish Explorer with generated fish detail pages.

**Architecture:** `docs/wiki/` remains the single human-edited prose source. `site/` becomes an Astro 7 + Starlight project with React islands only for interactive features. Fish metadata and renders are imported from the existing Tideborne public data, normalized into a typed local dataset, and statically rendered into browse/detail routes. The first milestone intentionally excludes FishScore calculation, Gear Builder, and homepage polish beyond the minimum shell required to make the Fish Explorer and docs usable.

**Tech Stack:** Astro 7.3.x, Starlight 0.42.x, `@astrojs/react` 6.0.x, React 19.2.x, Tailwind CSS 4.3.x, TypeScript, shadcn-derived primitives from the uploaded local UI source bundle, Vitest 5.x, Testing Library 16.x, GitHub Pages via `withastro/action@v6`.

**Spec:** `docs/superpowers/specs/2026-09-21-tideborne-official-field-guide-design.md`

## Global Constraints

- Work only on `wiki/official-field-guide`, which is based on `dev`. Never modify, merge, rebase, or retarget `main`.
- Preserve `docs/wiki/` as authoritative prose. Generated copies under `site/src/content/docs/` are build artifacts, not a second editing surface.
- Documentation target remains Tideborne 2.1.0, Minecraft 1.21.1, Fabric, Tide 2.1.1 unless the authoritative docs are deliberately updated.
- Do not create a second FishScore calculator, specimen model, gear registry, or other gameplay authority in website code.
- Reuse only the smallest UI component source needed from `UI_LIBRARY_COMPLETE.zip`; normalize all copied components to Tideborne tokens.
- Foundation component family: shadcn/ui. Kibo UI and Motion Primitives are reserved for later milestones unless a tested need appears.
- No Aceternity, RewampUI, React Bits, WebGL, canvas, or particle dependency in this milestone.
- Mobile layouts reflow intentionally; do not shrink the desktop filter sidebar into a narrow column.
- Keyboard operation, visible focus, semantic controls, sufficient contrast, non-color status cues, and reduced-motion support are required.
- Ordinary documentation pages should remain nearly JavaScript-free.
- Build must succeed as a static GitHub Pages site under the repository base path `/TIDEBORNE`.

## Review Focus

- **Base-path navigation:** every asset/link must work from `/TIDEBORNE/`, not only from a local root server. Task 1 owns a production-build assertion for this.
- **Missing or partial fish metadata:** a fish with no render, habitat, or optional field must still produce a usable card/detail page. Tasks 4 and 6 own these tests.
- **Filter combinations with zero matches:** the Fish Explorer must show a clear empty state and a working reset path rather than a blank grid. Task 5 owns this test.
- **Keyboard/mobile filters:** search, checkboxes, filter-sheet open/close, and reset must remain operable without a pointer. Task 5 owns this interaction test.
- **Generated-doc drift:** deleted/renamed source Markdown must not leave stale generated pages. Task 2 owns a clean-sync test.

## Follow-on plans after this milestone

These remain in the approved design spec but intentionally get separate implementation plans after this foundation is working:

1. **Canonical FishScore reference + calculator** - generated score constants/data, exact contribution breakdown, Motion Primitives animated score with reduced-motion fallback.
2. **Gear catalog + Gear Builder** - structured gear data, recipes, Kibo Combobox selection, canonical modifier/effect summaries.
3. **Homepage + global command search + visual polish** - real-feature-driven homepage, grouped Ctrl/Cmd+K search, restrained field-guide motion.
4. **Legacy-site migration and release cutover** - redirects/links from old Tideborne surfaces, CurseForge wiki link update, final Pages verification.

Each follow-on plan must keep the same source-of-truth rule: website tools render canonical/versioned Tideborne data and never become a second gameplay authority.
