# Stages 60-61 Legacy Recovery and Final Fishing Polish

Updated: 2026-08-30

Stages 60 and 61 complete the post-2.0 legacy recovery/admin tooling and the remaining
player-facing fishing integration polish. They do not change the frozen canonical specimen or
FishScore formulas.

## Stage 60: repair or reroll legacy fish preservation

Stage 60 adds operator-only server tooling for old Tideborne fish created before the current
Fishing System 2.0 canonical specimen schema.

### Repair

Supported targets are the held item and the player's inventory:

```text
/tideborne fishing repair held
/tideborne fishing repair inventory
```

Repair is intentionally preservation-first. It calls the existing
`CanonicalSpecimenStorage` legacy migration boundary rather than `SpecimenGenerator`.
Recoverable state is therefore normalized into current canonical V2 data without creating a
second independent specimen roll.

Where present in the legacy payload, migration preserves or deterministically reconstructs the
same supported identity already frozen by the legacy migration system, including:

- registered Tide species;
- deterministic specimen seed;
- natural percentile and/or recoverable physical size;
- Giant/Dwarf body type;
- legacy Condition mappings;
- legacy Pigmentation mappings;
- legacy Perfect Specimen mapping;
- compatible non-specimen stack metadata.

Canonical FishScore is calculated from the final migrated specimen through the existing V2
score service when a usable saved score is not already authoritative.

Repair is idempotent. A current canonical fish is reported as current rather than migrated a
second time. Unsupported, malformed, incomplete, newer-schema, and non-fish stacks fail closed.

### Destructive reroll

Supported destructive targets are:

```text
/tideborne fishing reroll held --confirm
/tideborne fishing reroll inventory --confirm
```

Reroll intentionally replaces the specimen with newly generated canonical data while retaining
the registered Tide fish species/item. The `--confirm` literal is mandatory. Calling the reroll
target without confirmation performs no migration and no write, so legacy identity cannot be
accidentally erased by an incomplete admin command.

Both repair and reroll require operator permission level 2 and execute on the server. Clients do
not author canonical specimen values.

### Stage 60 tests

`LegacyFishRecoveryGameTests` covers:

- deterministic repair of identical legacy state;
- preservation of legacy seed, percentile, physical length, Giant/Dwarf, mapped traits, and
  canonical FishScore generation;
- repair idempotence after the current canonical payload is written;
- unconfirmed reroll rejection with no mutation or implicit repair;
- deterministic confirmed reroll for an explicit replacement seed;
- current-schema canonical persistence after reroll.

More command-facing documentation is in `docs/FISHING_RECOVERY.md`.

## Stage 61: final fishing integration and polish

### Legitimate crate/reward fish progression

The progression fix is placed at Tide's existing server-side `TidePlayerData.logCatch` boundary
rather than in crate weighting or in a parallel crate-specific Journal system.

`CrateFishProgressionBridge` recognizes a registered Tide fish that reaches normal catch
accounting with a valid physical length but lacks canonical specimen identity. It then uses the
existing deterministic legacy/persistence migration machinery to create the one canonical
representation before Tide's normal accounting path runs.

This preserves the normal authority chain for:

- Tide catch/discovery progression;
- Team Journal capture;
- history and record updates;
- leaderboard/top-fish projections;
- canonical score consumers.

A fish that already has current canonical specimen state is left authoritative and is not
rerolled or regenerated by the bridge. The bridge does not alter crate category weighting or
crate reward selection itself.

`CrateFishProgressionBridgeGameTests` covers deterministic canonicalization of a legitimate
length-bearing Tide fish and preservation of already-canonical specimen identity.

### Top Fish specimen detail layout

The Stage 59 canonical projection and shared formatters remain in place. Stage 61 reorganizes
the cramped Top Fish specimen panel so important fields use human-readable labels rather than
abbreviations.

The panel now presents canonical values such as:

- FishScore;
- Percentile;
- Length;
- Body Type;
- Condition;
- Pigmentation;
- Quality.

Trait values retain the established visual color conventions. Bounded text and hover detail
remain available for values that do not fit the allocated panel width. No Top Fish/UI path
generates, mutates, rerolls, or rescales specimen state.
